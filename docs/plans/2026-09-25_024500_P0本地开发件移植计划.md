## 现状 / 目标 / 差距

- **现状（上游 caa51474）**：`apps/web` 是 monorepo 结构；`apps/web/lib/db/drizzle.ts` 已把 D1 初始化抽到 `@mahoshojo/hosted-runtime/db/drizzle`；无任何本地运行模式；`apps/web/lib/database/schema.sql` 保留。
- **目标**：在 WSL/本地开发时，通过 `MAHOSHOJO_RUNTIME_MODE=local` 使用本地 PostgreSQL 模拟 D1（SQL 兼容转换 + schema 初始化），并把 R2 对象读写映射到本地目录 `.local/objects/`，与 Cloudflare 生产行为保持一致。
- **差距**：上游没有 runtime-mode、local-postgres client、本地 R2、`dev:local` 脚本；`drizzle.ts`/`r2.ts`/`next.config.ts`/`package.json`/`.gitignore`/`env.example` 需要三方合并。

1. 逐个落文件（新增 4 个 + 合并 6 个 + 测试 1 个）
2. `pnpm install`（装 `pg`，检查是否进入 Edge bundle——`pg` 只在 `server-only` 的 local-postgres client 内 `eval('require')` 动态加载，不进 Next bundle）

## 风险

- `pg` 依赖进入 Edge bundle → 通过 server-only 动态加载规避；`build:cf` 验证
- 上游 `drizzle.ts`/`r2.ts` 与旧版差异较大 → 三方合并需逐函数核对
- 本地 schema 初始化读 `apps/web/lib/database/schema.sql`（路径需适配）

## 冒烟验证结果（2026-09-25）

在 WSL 内安装 PostgreSQL 16（`postgresqld-16.service`），创建 `mahoshojo` 角色/库后，
`MAHOSHOJO_RUNTIME_MODE=local` 冒烟测试 **2/2 通过**（`tests/local-runtime-smoke.test.ts`）。

冒烟暴露并修复了三处旧代码未覆盖的方言适配（旧分支本地开发件实际从未完整跑通）：

1. **`DATETIME` 类型** → `TIMESTAMP`（项目 schema.sql 使用 SQLite 方言 `DATETIME`，Postgres 无此类型）
2. **better-auth 域表前置**：业务 schema.sql 的 `FOREIGN KEY ... REFERENCES ba_user(id)` 要求先建表；
   本地初始化改为从仓库 `drizzle/0000_auth_domain_bootstrap.sql` 提取 `ba_user` 建表块并先执行
   （Postgres 严格校验 FK 目标，SQLite 不校验）
3. **INSERT 布尔字面量**：schema.sql 含 `INSERT OR IGNORE INTO badges ... is_active ... 1`，
   新增列名感知转换，把 BOOLEAN 列位置的裸 `0/1` 转 `FALSE/TRUE`（引号/嵌套感知，不误伤字符串与整数列）

相关修改集中在 `apps/web/lib/db/local-postgres-d1-client.ts`。
