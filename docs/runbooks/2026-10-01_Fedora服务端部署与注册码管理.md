# Fedora 服务端部署与注册码管理

状态：代码与本地验证完成；目标 Fedora 服务器部署、D1 migration 和 secret 配置仍需在目标环境受控执行。

## 1. 部署边界

本项目当前不是“全部服务在 Fedora 本地数据库运行”的单体应用：

- `apps/web`：Next/OpenNext Web、Better Auth 注册入口和 D1/R2 业务数据，生产默认部署到 Cloudflare Worker。
- `apps/api`：Fedora 上运行的 Hono/Node 主服务，使用 Redis、D1 Gateway、R2 和 Provider 配置。
- `apps/admin`：独立 Cloudflare Admin Worker，不建议部署到 Fedora；其注册码管理通过 Admin Worker 操作共享 D1。

因此 Fedora 主机负责 `apps/api`，注册码由 `admin.mahoshojo.colanns.me` 的 Admin 页面发放。若只上传 Hono bundle，不会提供 Web 注册页面，也不能绕过 Cloudflare Web 的注册码校验。

## 2. Fedora 主机准备

以下命令在 Fedora 服务器执行。使用有 sudo 权限的部署用户，不要使用 root 直接运行应用；应用容器使用 rootless Podman。

```bash
sudo dnf upgrade -y
sudo dnf install -y git curl ca-certificates openssl policycoreutils-python-utils podman podman-compose
```

确认 rootless Podman 与 Compose 可用：

```bash
podman version
podman compose version
```

部署脚本还要求 `base64 curl flock head id mktemp realpath sha256sum stat podman`，Fedora 基础系统通常已提供这些工具。

## 3. 构建 Fedora/Hono release

推荐在 Linux CI 或 Fedora 构建机执行，避免 Windows 的符号链接限制：

```bash
git clone <仓库地址> /opt/src/MahoShojo-Generator
cd /opt/src/MahoShojo-Generator
git checkout <已审阅提交 SHA>
corepack enable
corepack prepare pnpm@11.3.0 --activate
pnpm install --frozen-lockfile
pnpm run ci:verify
pnpm --filter @mahoshojo/api run deploy:prepare
```

`deploy:prepare` 会生成 `apps/api/dist/index.mjs`。正式 release 还需要一起复制：

- `apps/api/deploy/compose.yml`
- `apps/api/deploy/deploy-bundle.sh`
- `apps/api/scripts/backup-local-objects.sh`
- `apps/api/scripts/mahoshojo-local-object-backup.service`
- `apps/api/scripts/mahoshojo-local-object-backup.timer`
- `apps/api/dist/release.manifest`
- `apps/api/dist/release.sha256`

release ID 是 `release.sha256` 中的 64 位 SHA-256。不要只复制 `index.mjs`，部署脚本会校验整个 release manifest。

## 4. Fedora 目录与权限

生产 Hono 目录固定为：

```text
/opt/mahoshojo-hono/
  .env.hono                 # 0600，部署用户所有
  current -> releases/<sha256>
  releases/<sha256>/
```

初始化目录：

```bash
sudo install -d -o "$USER" -g "$USER" -m 0750 /opt/mahoshojo-hono/releases
sudo install -d -o "$USER" -g "$USER" -m 0750 /opt/mahoshojo-hono
install -m 0600 /dev/null /opt/mahoshojo-hono/.env.hono
```

## 5. Hono 环境变量

从 `apps/api/env.example` 准备 `/opt/mahoshojo-hono/.env.hono`。生产至少需要：

```dotenv
NODE_ENV=production
HOSTED_API_ENVIRONMENT=production
HONO_HOST=0.0.0.0
HONO_PORT=8787
HONO_AUTH_MODE=bearer
HONO_CORS_ORIGINS=https://mahoshojo.colanns.me
ARENA_ROOM_ALLOWED_ORIGINS=https://mahoshojo.colanns.me
ARENA_MULTIPLAYER_ENABLED=false
REDIS_REQUIRED=true
REDIS_HOST=redis
REDIS_PORT=6379
D1_REQUIRED=true
D1_GATEWAY_URL=https://<d1-gateway-origin>
D1_GATEWAY_HMAC_SECRET=<至少32字符随机值>
AI_PROVIDERS_CONFIG=<受控 JSON 配置>
SIGNATURE_SECRET_KEY=<独立随机值>
ARENA_FINALIZATION_URL=https://mahoshojo.colanns.me
ARENA_FINALIZATION_HMAC_SECRET=<另一组独立随机值>
# OBJECT_STORAGE_MODE=local 时不需要 R2_* 配置
OBJECT_STORAGE_MODE=local
LOCAL_OBJECTS_DIR=/data/objects
LOCAL_BACKUP_DIR=/data/backups
LOCAL_BACKUP_RETENTION_DAYS=14
```

注意：`BETTER_AUTH_SECRET` 不是 Hono bearer 模式的必填项，但 Web 的注册码注册和 Better Auth 迁移链路必须在 Cloudflare Web 环境正确配置相同的 Web-side secret。不要把该 secret 写入浏览器或公开仓库。

## 6. 启动 Redis 与 Hono

Hono production compose 依赖一个名为 `mahoshojo-redis` 的外部 Podman network。若 Redis 已由服务器现有控制面管理，确认该网络和 Redis service 名称存在；不要让 Hono 创建第二套业务 Redis。

```bash
podman network inspect mahoshojo-redis >/dev/null
```

把 release 上传到目标目录后执行：

```bash
release_id=<64位release.sha256中的值>
release_dir=/opt/mahoshojo-hono/releases/$release_id

sudo install -d -o "$USER" -g "$USER" -m 0750 "$release_dir"
scp apps/api/dist/index.mjs apps/api/dist/compose.yml apps/api/dist/deploy-bundle.sh \
  apps/api/dist/backup-local-objects.sh apps/api/dist/mahoshojo-local-object-backup.service \
  apps/api/dist/mahoshojo-local-object-backup.timer \
  apps/api/dist/release.manifest apps/api/dist/release.sha256 \
  fedora-host:"$release_dir/"
ssh fedora-host "chmod 0755 '$release_dir/deploy-bundle.sh' && \
  HONO_HOSTED_API_ENVIRONMENT=production '$release_dir/deploy-bundle.sh' publish '$release_id' https://maho.archine-database.top"
```

部署脚本会校验 SHA、运行 rootless Podman compose config-check、启动 candidate、等待本机 readiness，再执行公网 health/contract smoke；失败时保留 previous release 并恢复服务。生产默认绑定 `127.0.0.1:11020`，不触碰旧服务的 `11010/11011`。

本地对象目录和备份目录（两者必须位于独立目录，不能互相嵌套）：

```bash
install -d -m 0750 /opt/mahoshojo-hono/data/objects /opt/mahoshojo-hono/data/backups
```

每日备份示例：

```bash
LOCAL_OBJECTS_DIR=/opt/mahoshojo-hono/data/objects \
LOCAL_BACKUP_DIR=/opt/mahoshojo-hono/data/backups \
LOCAL_BACKUP_RETENTION_DAYS=14 \
  apps/api/scripts/backup-local-objects.sh
```

安装用户级 systemd 定时任务（release 上传完成后执行）：

```bash
mkdir -p ~/.config/systemd/user
install -m 0644 "$release_dir/mahoshojo-local-object-backup.service" ~/.config/systemd/user/
install -m 0644 "$release_dir/mahoshojo-local-object-backup.timer" ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now mahoshojo-local-object-backup.timer
systemctl --user status mahoshojo-local-object-backup.timer
```

若要求用户退出 SSH 后仍运行，需在已确认的 Fedora 用户会话策略中启用 `loginctl enable-linger "$USER"`；这不会创建或修改系统级旧服务。

备份应使用用户级 systemd timer 或外部备份系统，并复制到另一块磁盘/另一台主机；同一磁盘上的压缩包不构成灾备。

## 7. Caddy / TLS

仓库的 `apps/api/deploy/Caddyfile` 将 `maho.archine-database.top` 反代到 `127.0.0.1:11020`。Fedora 上若使用 Caddy，请先备份并人工合并现有 `/etc/caddy/Caddyfile`，不要直接覆盖既有 Arcane vhost：

```bash
sudo dnf install -y caddy
sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.backup.$(date +%Y%m%d%H%M%S)
# 将 apps/api/deploy/Caddyfile 的 maho.archine-database.top 块合并到现有配置
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl enable --now caddy
sudo systemctl reload caddy
```

只开放 80/443 给公网；Hono 的 11020 仅监听回环地址，Redis、D1 Gateway 和管理端口不要公开。

## 8. Web/注册码上线顺序

1. 先在 Cloudflare Web 环境应用 `0022_registration_codes.sql`。
2. 部署包含注册码校验的 Web candidate，确认 `BETTER_AUTH_SECRET` 和 D1 binding 正确。
3. 先访问 Web 注册页确认无注册码返回 `400`，错误 Better Auth 直达 `/api/auth/sign-up/email` 返回 `403 REGISTRATION_CODE_REQUIRED`。
4. 通过 Admin Worker 以 `registration.write` capability 创建注册码。
5. Admin 创建响应中只保存/展示本次生成的明文注册码；列表只显示 prefix、次数、状态和到期时间。
6. 用注册码完成一次注册，再验证重复使用、超次数、过期、撤销和注册失败释放行为。
7. 生产首次开启 Admin writer 前，保持 `ADMIN_ENABLED_ACTIONS=[]` 完成只读验收，再单独启用 `registration-codes.create` / `registration-codes.revoke`。

## 9. 回滚

- Hono：使用上一份已校验 release 的 `deploy-bundle.sh rollback`。
- Web：按现有 Cloudflare production release workflow 回滚 candidate；不要删除 `registration_codes` 或 claims 表。
- Admin：关闭 `registration.write`，必要时回退 Admin Worker；不删除注册码审计和历史 claims。
- 如果注册码 migration 已执行，回滚代码仍保留表结构，旧 Web 版本必须继续拒绝无注册码的新注册，不能回退到可公开注册的旧 handler。

## 10. 本地对象存储限制

本地对象模式只让 Fedora Hono 能保存和读取 Arena 正文；D1 仍只保存 metadata/reference。Cloudflare Web DR 和 Admin Worker 不能直接读取 Fedora 文件系统，因此依赖 R2 binding 的 Web/Admin 对象能力必须保持关闭或另行实现受保护的 storage gateway。不能把本地磁盘描述为 R2 或跨故障域 durable authority。

## 11. 不执行的操作

本说明不包含实际服务器连接、SSH 写入、Cloudflare remote migration、Access bootstrap、secret 轮换或 production deploy。上述操作必须在目标、提交 SHA、备份点和维护窗口明确后单独授权。
